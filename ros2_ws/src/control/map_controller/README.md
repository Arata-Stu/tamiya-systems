# map_controller

MAP-style controller for local `race_planning_msgs/msg/Trajectory` references.

The controller assumes the reference points are already expressed in
`base_link` with `x` forward and `y` left. It does not apply TF transforms.

Inputs:

- `/autonomous/trajectory_reference`
- `/visual_slam/tracking/odometry`

Output:

- `/autonomous/cmd_drive`

Each `trajectory_reference` point can carry `speed_mps`. The controller uses it
as the reference speed, then clamps it with `min_speed` / `max_speed`. If the
message has no positive speed, `fallback_speed` is used.
When `system_launch use_speed_controller=true` is enabled, this output speed is
treated as a target vehicle speed `[m/s]`; the separate `speed_controller`
converts it into JetRacer throttle just before the vehicle driver.

Lateral control computes a desired lateral acceleration with an L1 target and
converts that acceleration into a steering angle through a lookup table. When
`lookup_table_csv_path` is empty or invalid, the controller falls back to a
kinematic bicycle conversion so the package is still usable before a lookup
table is identified.

```bash
ros2 launch map_controller map_controller.launch.xml
```

With the system launch:

```bash
ros2 launch system_launch system.launch.xml use_map_controller:=true
```

Main parameters:

- `lookup_table_csv_path`
  - CSV generated by `python_ws/data_analysis/build_map_steering_lookup.py`
- `use_lookup_table`
  - `true` to use the CSV if present, `false` to force the kinematic fallback
- `m_l1`, `q_l1`, `t_clip_min`, `t_clip_max`
  - L1 lookahead shaping
- `speed_lookahead`, `speed_lookahead_for_steer`
  - simple delay compensation
